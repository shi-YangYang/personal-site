# Decision: Use HeroUI for Admin and Interactive UI

## Context

The project's interactive controls were hand-built React + Tailwind components. The owner asked to use an existing UI library instead of maintaining primitives.

## Decision

- Use `@heroui/react` 3.x (React Aria based) with the existing Tailwind CSS 4 setup.
- Map HeroUI theme tokens to the site's cyber-green CSS variables.
- Migrate every native button, input, textarea, select, and admin tab to HeroUI.
- Use HeroUI Tabs for the Admin section switcher, including keyboard navigation and scroll reset on switch.
- Keep the custom Hero, terminal, 3D, and visual section shells; they are part of the site identity, not generic form primitives.

## Reason

HeroUI supports React 19, Tailwind 4, and Next.js without a provider. It gives accessible Select, Input, Button, Dialog, and other primitives while allowing the existing theme to remain.

## Consequences

- `@heroui/react` and `@heroui/styles` are dependencies.
- HeroUI CSS is imported once in `app/globals.css`.
- Admin and future interactive surfaces should use HeroUI components instead of new hand-built primitives.
- Public-site visual components remain custom.
